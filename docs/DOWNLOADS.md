# Загрузки и офлайн

Требования — [SPEC.md](../SPEC.md) §7.6. **Статус: реализовано в P4 (mock +
real download одного трека); полный album/playlist soak — pending.**

## 7. API (P4, реализовано)
На P1 существует только чистая функция раскладки путей
(`backend/app/downloads/paths.py`) и её тесты — SPEC §13 требует тест шаблона
путей уже в P1. Пайплайна, API `/downloads` и UI загрузок нет.

## 1. Источник и права

- Источник v1 — аккаунт владельца Яндекс Музыки при активной подписке.
- Скачивание — только для личного офлайн-доступа; распространение запрещено
  (docs/LEGAL.md).
- encraw расшифровывается библиотекой `yandex_music` (extra `crypto`), не своей
  реализацией.
- Качество выбирается в настройках (`downloads.quality`: `auto | flac | aac |
  mp3`) и действует на новые задачи; страница «Загрузки» показывает селектор.
  `auto` — FLAC → AAC → MP3 320; явный выбор тоже фолбэкает, если семья
  недоступна. В UI всегда показывается фактический формат, а не обещанный.
- Ссылки на аудио получаются непосредственно перед загрузкой и не хранятся как
  истина (они истекают). Подписанный URL при необходимости переписывается на
  соседний CDN-edge (`CdnRouter`).

## 2. Очередь

- Одна параллельная загрузка (1 worker), остальные — `queued`.
- Пауза 2–5 с между треками (антибан), настраиваемая.
- Ретраи с exponential backoff (2, 5, 15, 60, 180 с), не более 5 попыток.
- Докачка: HTTP Range от `bytes_done`, если сервер поддерживает; иначе с начала.
- Очередь переживает рестарт: состояние в `download_tasks`; при старте
  `downloading` → `queued` (частичный файл сохраняется для докачки).
- Отмена: `cancelled`, частичный `.part` удаляется по maintenance/cleanup.
- Приоритет — поле `priority`; v1 UI не управляет, порядок FIFO по `created_at`.

## 3. Пайплайн

```text
POST /downloads (track_id / album / playlist)
  → создать download_tasks (status=queued, цель — track)
  → worker:
      1. resolve audio source (quality fallback)
      2. HEAD/Range → bytes_total
      3. потоковая запись в <target>.part  (httpx/aiohttp, chunks)
      4. проверка размера/заголовка/декодера (mutagen)
      5. decrypt encraw (библиотека), если нужно
      6. атомарный rename .part → финальный путь
      7. запись тегов + обложки (+ .lrc, если текст есть)
      8. INSERT/UPDATE media_files, verified_at=now
      9. пересчитать признаки трека: has_local_file=1, file_missing=0
     10. status=completed; WS download.progress/done (P4)
```

**Offline-статус ставится только после проверки файла** (размер, mutagen может
прочитать, длительность в допуске). До этого трек остаётся `online`.

Ошибка на любом шаге → `failed` с `error`, `.part` сохранён для докачки
(если ошибка сетевая) или удалён (если битый контент).

## 4. Раскладка путей

Шаблон по умолчанию (SPEC §7.6):

```text
{artists}/{album} ({year})/Disc {disc}/{track:02d} - {title}{ext}
```

Пример:

```text
Тестовый Оркестр/Mock Album (2024)/Disc 1/01 - Ночной эфир.mp3
```

Правила рендера (`app/downloads/paths.py`, реализовано и покрыто тестами):

- Плейсхолдеры: `artists`, `album`, `year`, `disc`, `track`, `title`, `ext`.
  `ext` — с ведущей точкой (`.flac`), нормализуется из фактического формата.
- `track`/`disc` поддерживают format spec (`{track:02d}`); при отсутствии номера
  подставляется `1` для диска и `0` для трека.
- `year` отсутствует → сегмент `()`/` ( )` вычищается, лишние пробелы сжимаются.
- `artists` — только primary artist для пути (несколько артистов разделены `, `,
  но в пути это допустимо; при желании — первый).
- Запрещённые символы `< > : " / \ | ? *`, control chars → `_`. Точки/пробелы
  в конце компонента удаляются. Зарезервированные имена Windows
  (`CON`, `PRN`, `AUX`, `NUL`, `COM1..9`, `LPT1..9`) получают суффикс `_`.
- Компонент длиннее 120 символов обрезается (по кодовым точкам, без разрыва
  суррогатной пары), расширение сохраняется.
- `..` и `.` как компоненты запрещены: вычищаются. Итоговый путь обязан
  оставаться внутри корня загрузок — проверка `Path.resolve().is_relative_to(root)`
  (path traversal).
- Unicode (кириллица) сохраняется как есть; NFC-нормализация — на P4.
- Коллизия путей: добавляется ` (2)`, ` (3)` перед расширением.

## 5. Теги и обложки

- Контейнеры: MP3 → ID3v2.4 (UTF-8), FLAC → Vorbis Comments, M4A/AAC → MP4 ilst.
- Поля: title, artists (все), albumartist, album, year, genre, tracknumber,
  discnumber, label, cover.
- Обложка: `cover.jpg` 1000px в папке альбома (если ещё нет) + встроенная
  выбранного размера (настройка 300/600/1000).
- Текст: `.lrc` рядом с файлом при наличии синхронизированного текста (P5
  добавляет кэш; P4 пишет файл, если текст уже получен).
- Теги пишутся mutagen после успешной записи аудио; ошибка тегов не отменяет
  загрузку (warning), но `verified_at` ставится после успешной проверки.

## 6. Хранилище

- Каталог загрузок настраивается (`paths.downloads`, обычно USB).
- Лимит кэша загрузок (настройка) + автоочистка: самые старые/неиграемые
  `media_files` с `role=download` удаляются, пока размер > лимита.
- Удаление файла пользователем = `file_missing=1`, `has_local_file=0` после
  проверки; запись в БД не удаляется (история/плейлисты сохраняются).
- Загрузки не пишутся на SD по умолчанию: UI предупреждает, если путь на SD.

## 7. API (P4, реализовано)

Актуальный контракт — [API.md](API.md) §8. Кратко:
`POST /downloads {track_id|album_id|playlist_id, priority?}`, `GET /downloads`,
`DELETE /{id}`, `POST /{id}/cancel|retry`; WS `download.*` с `{task: DownloadTask}`.

## 8. Тесты P4 (реализовано)

- Раскладка/санитизация — уже есть на P1.
- Fallback качества: FLAC недоступен → AAC скачан, бейдж честный.
- Докачка после обрыва; restart-safe (`downloading` → `queued`).
- Mock e2e: 11 сценариев; real download одного трека на Pi.
- Offline только после mutagen-проверки; битый файл → `failed`.
- Идемпотентность: повторная загрузка не создаёт второй `media_files`.
- Лимит кэша и автоочистка.
